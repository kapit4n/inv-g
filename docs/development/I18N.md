# Internationalization (i18n)

## Overview

Inventory Gear uses **i18next** with **react-i18next** for internationalization. Spanish (`es`) is the default language, with English (`en`) also fully translated. The architecture supports adding new languages with minimal effort.

## Architecture

### How i18n is Set Up

The i18n system is initialized in `src/i18n/config.ts`:

```ts
import i18n from "i18next"
import { initReactI18next } from "react-i18next"

import esCommon from "./locales/es/common.json"
import enCommon from "./locales/en/common.json"
// ... all other namespaces imported per locale

const resources = {
  es: {
    common: esCommon,
    dashboard: esDashboard,
    inventory: esInventory,
    // ... 18 namespaces total
  },
  en: {
    common: enCommon,
    dashboard: enDashboard,
    inventory: enInventory,
    // ... 18 namespaces total
  },
}

i18n.use(initReactI18next).init({
  resources,
  lng: "es",           // default language
  fallbackLng: "es",   // fallback if key missing
  defaultNS: "common", // default namespace
  ns: ["common", "dashboard", "inventory", "sales", "purchases",
       "customers", "suppliers", "vehicles", "warehouse", "reports",
       "settings", "auth", "employees", "validation", "errors",
       "help", "crm", "admin"],
  nsSeparator: ".",
  interpolation: { escapeValue: false },
  returnObjects: true,
})
```

### Namespaces

There are **18 translation namespaces**, each as a separate JSON file per locale:

| Namespace    | File                          | Purpose                              |
|--------------|-------------------------------|--------------------------------------|
| `common`     | `{lang}/common.json`          | Buttons, labels, status, generic UI  |
| `dashboard`  | `{lang}/dashboard.json`       | Dashboard page                       |
| `inventory`  | `{lang}/inventory.json`       | Inventory management                 |
| `sales`      | `{lang}/sales.json`           | Sales and POS                        |
| `purchases`  | `{lang}/purchases.json`       | Purchase orders                      |
| `customers`  | `{lang}/customers.json`       | Customer management                  |
| `suppliers`  | `{lang}/suppliers.json`       | Supplier management                  |
| `vehicles`   | `{lang}/vehicles.json`        | Vehicle tracking                     |
| `warehouse`  | `{lang}/warehouse.json`       | Warehouse management                 |
| `reports`    | `{lang}/reports.json`         | Reports and analytics (~296 keys)    |
| `settings`   | `{lang}/settings.json`        | Application settings                 |
| `auth`       | `{lang}/auth.json`            | Authentication                       |
| `employees`  | `{lang}/employees.json`       | Employee management                  |
| `validation` | `{lang}/validation.json`      | Form validation messages             |
| `errors`     | `{lang}/errors.json`          | Error messages                       |
| `help`       | `{lang}/help.json`            | Help and support                     |
| `crm`        | `{lang}/crm.json`             | CRM module                           |
| `admin`      | `{lang}/admin.json`           | Administration module                |

```
        └── ... (18 files)
```

## Translation Key Conventions

- **Dot notation**: `namespace.key.subkey` (e.g., `inventory.products.addProduct`)
- **Namespace prefix**: When using the default namespace, the key is just the path (e.g., `save`, `cancel`). When in a specific namespace, keys are relative to that namespace.
- **Descriptive keys**: Use meaningful names, not generic labels — `dashboard.recentActivity` not `dashboard.ra`.
- **No abbreviations**: `purchases.supplierPerformance` not `purchases.supPerf`.
- **Consistent casing**: camelCase for compound keys: `lowStockThreshold`, `reorderPoint`.
- **Group related keys**: Use nested JSON objects for logical grouping:

```json
{
  "products": {
    "addProduct": "Add Product",
    "editProduct": "Edit Product",
    "deleteProduct": "Delete Product"
  }
}
```

Called as: `t("inventory.products.addProduct")`

## Using Translations in Components

### Basic Usage

```tsx
import { useTranslation } from "react-i18next"

function MyComponent() {
  const { t } = useTranslation()
  return <h1>{t("dashboard.title")}</h1>
}
```

### With a Specific Namespace

```tsx
const { t } = useTranslation("inventory")
// Keys are scoped to inventory namespace:
t("products.addProduct")       // instead of t("inventory.products.addProduct")
```

### With Interpolation

```json
{
  "itemsCount": "{count} items"
}
```

```tsx
t("purchases.itemsCount", { count: 12 })
```

### With Pluralization

```json
{
  "item": "item",
  "item_plural": "items",
  "item_count": "{count} item",
  "item_count_plural": "{count} items"
}
```

```tsx
t("purchases.item_count", { count: 5 }) // "5 items"
t("purchases.item_count", { count: 1 }) // "1 item"
```

### With Nested Keys (using dot separator)

```json
{
  "products": {
    "form": {
      "name": "Product Name",
      "sku": "SKU"
    }
  }
}
```

```tsx
t("inventory.products.form.name")
```

## Adding a New Language

1. **Create locale folder**: `src/i18n/locales/fr/`

2. **Copy all JSON files** from `es/` and translate the values:
   - `fr/common.json`
   - `fr/dashboard.json`
   - ... (all 18 files)

3. **Register in `src/i18n/config.ts`**:

```ts
import frCommon from "./locales/fr/common.json"
import frDashboard from "./locales/fr/dashboard.json"
// ... import all 18 namespaces

const resources = {
  es: { /* existing */ },
  en: { /* existing */ },
  fr: {
    common: frCommon,
    dashboard: frDashboard,
    inventory: frInventory,
    // ... all namespaces
  },
}
```

4. **Add the language option** in the Settings page (settings editor in Admin module).

## Adding New Translation Keys

1. **Determine the correct namespace**: Reusable UI labels go in `common`. Feature-specific content goes in the feature's namespace (e.g., `inventory`, `sales`, `reports`).

2. **Add the key to both locales**:

```json
// es/inventory.json
{
  "workshops": {
    "title": "Talleres",
    "addWorkshop": "Agregar Taller"
  }
}
```

```json
// en/inventory.json
{
  "workshops": {
    "title": "Workshops",
    "addWorkshop": "Add Workshop"
  }
}
```

3. **Use in components**:

```tsx
const { t } = useTranslation("inventory")
t("workshops.title")
```

## Language Detection Priority

1. **Saved preference** — persisted in localStorage via Zustand (settings store).
2. **Spanish** — default fallback if no preference saved.

The language can be changed in the Settings page under General settings.

## Formatting

The application uses the browser's `Intl` API for formatting dates, numbers, and currency, which automatically adapts to the user's locale when a language is selected. This is configured per feature in the respective translation files.

## Best Practices

1. **Always use `t()`** — never hardcode user-facing strings.
2. **Keep translations in the correct namespace** — `common` for reusable labels, feature namespaces for specific content.
3. **Use interpolation for dynamic values** — don't concatenate translated strings.
4. **Group related keys** — use nested objects for logical grouping.
5. **One key per concept** — avoid duplicating translations for the same concept.
6. **Keep both locales in sync** — when adding a key to `es/`, add the corresponding key to `en/` immediately.
7. **Use `returnObjects: true`** — allows accessing nested objects in translations.
